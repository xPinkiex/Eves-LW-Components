Eve's Serial Port

A byte stream between a circuit and a TCP connection, like a UART whose other end is a network socket. A terminal on the PC can type into your computer and read what it writes, and the circuit can connect out.

Listen

A terminal connects to the block (telnet localhost 7000) and talks to the circuit.

Connect

The circuit opens a connection out, to any host and port.

Simple pins

8 bits in, 8 bits out, three strobes, five status lines. The network runs on a server thread.

How it works

The block keeps two queues of 4,096 bytes each, one for each direction. A thread on the game server moves bytes between the queues and the socket. The pins only touch the queues, so the circuit never waits for the network:

  • Sending: put a byte on TX0–TX7 and raise WR. The byte joins the send queue.
  • Receiving: while a received byte is waiting, RXV is high and the byte is on RX0–RX7. When RD falls, that byte is consumed and the next one shows, or RXV goes low.
  • Commands: bytes written with CMD high go to a command line instead of the network. A newline runs it.

The outputs are refreshed every tick. Bytes sent while nothing is connected are dropped.

Commands

Write the characters with CMD high, one WR pulse each, ending with a newline (\n) or a carriage return (\r). A new command first closes whatever was open.

CommandDoes
listen PORTWaits for connections on 127.0.0.1:PORT, only from the same machine. One at a time; when it closes, the block listens again.
listen ADDR:PORTThe same on another address. 0.0.0.0:PORT listens on every network interface, so other machines can connect. Only do that on a trusted network.
listen PORT telnetAs above, for a terminal:
  • it asks the telnet client for character mode, without local echo (the circuit echoes);
  • it removes telnet's control sequences from the input;
  • Enter (CR LF or CR NUL) arrives as one CR.
connect HOST:PORTConnects out, to a name or address. Gives up after 10 seconds (ERR).
closeCloses the connection and stops listening.
Connections aren't saved with the world. After a reload the circuit has to send its command again.

Connecting to it from the PC

On the machine running the game server (the host's own PC in single player):

telnet localhost 7000
# or, without telnet installed:
socat -,rawer,escape=0x1d TCP:localhost:7000      # Ctrl+] quits

From another machine, tunnel through SSH to the game server's machine:

ssh -L 7000:localhost:7000 you@gamepc
telnet localhost 7000

To reach a remote shell over SSH, the PC does the encryption and the block connects to a local bridge:

socat TCP-LISTEN:7001,bind=127.0.0.1,fork EXEC:"ssh user@host",pty

Then send connect 127.0.0.1:7001.

On a CPU bus

The usual way to use it from a CPU is as two memory-mapped registers, DATA and CTRL, one address apart:

RegisterReadWrite
DATAThe status word; the received byte in it is consumedSends the low byte
CTRLThe status word; nothing consumedA byte of a command
  • TX0–TX7 ← data bus bits 0–7.
  • WR ← the write strobe, for either register.
  • CMD ← the address bit that tells CTRL from DATA.
  • RD ← the read strobe, for DATA only. The byte is consumed on the falling edge, after the CPU has taken it.
  • Outputs 0–12 → data bus bits 0–12, on a read of either register: the byte, then RXV, CONN, LSN, TXR, ERR.

A program then:

  1. writes a command to CTRL, e.g. listen 7000 telnet\n;
  2. reads DATA in its main loop: a byte arrived when RXV is set;
  3. writes bytes to DATA while TXR is set.
Example: the LW32. The LW32 toolchain has this as its serial device at 0x70000 (DATA) and 0x70004 (CTRL), with LW32_SERIAL and the LW32_SER_* bits in lw32_io.h. Its emulator models the block with real sockets (lw32-emu --serial). LW-CPU-OS runs a shell on it, so telnet localhost 7000 gives you its command line.
#define DATA LW32_SERIAL[0]
#define CTRL LW32_SERIAL[1]
static void command(const char *s) { while (*s) CTRL = *s++; CTRL = '\n'; }

command("listen 7000 telnet");
for (;;) {
    unsigned st = DATA;                     /* status and a byte, consumed */
    if (st & LW32_SER_RXV) {
        while (!(CTRL & LW32_SER_TXR)) {}  /* room to send */
        DATA = LW32_SER_BYTE(st);             /* echo it */
    }
}

Details

  • Security: by default it listens only on 127.0.0.1, so only the game server's own machine can connect. Anyone who reaches the port types into your circuit.
  • Connections: one at a time while listening; a second client waits until the first closes.
  • Latency: the server thread checks the socket every 2 ms. The circuit sees a byte on the next tick after it arrives.
  • Speed: as fast as the circuit takes the bytes.
