Eve's RAM

64 KB of byte-wide memory with 16 address bits, one write port and an in-game editor. A program memory, a data RAM, or both.

Pins

Back face: inputs Front face: outputs

Each peg is drawn at its x position in the block's prefab, from x = 0 on the left. Small grey numbers are the peg indexes in the code; the upper row is y = 1.5, the lower y = 0.5.

PegsNameWhat it does
in 0–15A0–A15The address (peg n is bit n; A15 on the left).
in 16WERising edge: the byte on D0–D7 is written at the address.
in 17–24D0–D7The byte to write (peg 17 is bit 0).
out 0–7Q0–Q7The byte at the address, always (peg 0 is bit 0).

Behaviour

  • Reading is continuous: Q0–Q7 show the byte at A0–A15 and follow every change of the address. A byte never written, or past what was loaded, reads 0.
  • Writing takes one rising edge of WE. Hold the address and data steady across it.
  • Size: 65,536 bytes. Memory is only used up to the highest byte loaded or written.

Contents

  • Press X while looking at the block to open the editor. Type or paste bytes, or name a file with @file, and press Apply.
  • What the world keeps: the editor's text. After a reload the block holds what that text gives, and files are read again. Bytes the circuit wrote are lost on a reload when the block has editor text. A block with no text keeps its bytes.
  • Restore in the editor puts back the last applied contents, undoing the circuit's writes.
For more than 64 KB, use several blocks with an address decoder: one block per 64 KB, chosen by the high address bits. A file loads at most one block; split bigger images into one file per block.
